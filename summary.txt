1. EXECUTIVE OVERVIEW
================================================================================
SkillBridge (SIH26044) is an AI-driven, evidence-based academia-industry 
collaboration platform designed to bridge the gap between student competencies 
and corporate requirements. The project connects 4 distinct stakeholders:
  - Students: Evidence-based skill profiles, skill gap analysis, AI roadmaps, live projects.
  - Companies: Skill-weighted postings, explainable candidate match ranking, project sponsorship.
  - Faculty: Student mentorship, skill verification/sign-off, academic tracking.
  - Institutions: Accreditation compliance, macro skill gap reporting, placement insights.

The repository is structured as a full-stack monorepo:
  - /server: Node.js (ES Modules) + Express + MongoDB/Mongoose + Google Gemini AI.
  - /client: React 19 + Vite + Tailwind CSS + Lucide Icons + React Router DOM.

2.2 DATABASE MODELS & SCHEMAS (server/src/models)
--------------------------------------------------------------------------------
All schemas are strictly typed with Mongoose validation, references, and indexes:

1. User.js:
   - Base authentication identity for all platform actors.
   - Fields: name, email (unique, lowercase), password (bcrypt hashed pre-save),
     role (enum: ['student', 'company', 'faculty', 'institution']), isVerified.
   - Instance method: comparePassword(candidatePassword).

2. StudentProfile.js:
   - 1:1 linked with User.
   - Academic details: college, degree, branch, year (1-6), bio, contactNumber.
   - Resumes & Links: resumeUrl, resumeFileName, portfolio items (project, certificate, achievement).
   - Skills Vector (Evidence-Based): Embedded array containing:
     * skill (ObjectId ref 'Skill')
     * level (0-100 numeric score)
     * verified (boolean)
     * evidenceType ('assessment'|'certificate'|'project'|'faculty-signoff'|'self-reported')
     * evidenceRef (URL or Project ID)
     * verifiedBy (ObjectId ref 'User')
     * verifiedAt (Date)
   - Target Roles & Roadmap milestones.

3. CompanyProfile.js:
   - 1:1 linked with User.
   - Details: companyName, industry, website, logoUrl, location, about, companySize, contactNumber.

4. FacultyProfile.js:
   - 1:1 linked with User.
   - Academic link: institution (ObjectId ref 'InstitutionProfile'), department, designation.
   - Expertise & Tracking: expertiseSkills (ref 'Skill'), bio, mentorshipCount.

5. InstitutionProfile.js:
   - 1:1 linked with User.
   - Accreditation & Analytics: institutionName, address, accreditation, website,
     totalStudents, totalFaculty, contactNumber.

6. Opportunity.js:
   - Created by companies for jobs, internships, or live industry projects.
   - Fields: postedBy (ref 'User'), company (ref 'CompanyProfile'), title, description,
     type ('internship'|'job'|'project'), location, isRemote, stipend, applicationDeadline.
   - requiredSkills: Array of { skill: ref 'Skill', minLevel: 0-100, weight: 0-1 }.
   - applicants: Embedded array of { student: ref 'User', status, matchScore, matchReasoning, appliedAt }.
     Status enum: ['applied', 'reviewing', 'shortlisted', 'interview', 'hired', 'accepted', 'rejected'].

7. Skill.js:
   - Global canonical taxonomy of competencies.
   - Fields: name (unique), category ('technical'|'soft'|'domain'|'tool'), aliases[],
     relatedSkills[], ncrfCode (India NSQF/NCrF alignment), description.

8. LiveProject.js:
   - Real-world project pipeline connecting industry, faculty mentors, and students.
   - Tracks milestones, status, student team, faculty supervisor, and skillsAwarded upon completion.

2.3 AUTHENTICATION & AUTHORIZATION (server/src/middleware/auth.js)
--------------------------------------------------------------------------------
- protect: Middleware extracting and verifying Bearer JWT tokens from headers;
  attaches decoded { id, role } to req.user.
- restrictTo(...roles): RBAC authorization guard returning 403 Forbidden if the
  authenticated user's role does not match permitted roles.

2.4 API CONTROLLERS & ENDPOINTS
--------------------------------------------------------------------------------
1. Auth Endpoints (/api/auth) -> authRoutes.js & authController.js:
   - POST /api/auth/signup: Registers User and atomically provisions the role-specific
     profile document (StudentProfile, CompanyProfile, FacultyProfile, InstitutionProfile).
   - POST /api/auth/login: Validates credentials and returns signed JWT token.
   - GET /api/auth/me: Returns current authenticated user metadata.

2. Profile Endpoints (/api/profile) -> profileRoutes.js & profileController.js:
   - GET /api/profile/me: Protected; dynamically resolves and returns the logged-in
     user's profile with populated Skill references.
   - PUT /api/profile/me: Protected; whitelist updates profile data.
     * CRITICAL ARRAY MERGE: For students, merges skills by Skill ObjectId. Updates
       level and evidence without wiping project-verified skills or sign-offs.
   - GET /api/profile/:id: Protected/Public; fetches any profile across all 4 collections
     by either profile _id or user _id with populated user/skill data.

3. Opportunity Endpoints (/api/opportunities) -> opportunityRoutes.js & opportunityController.js:
   - POST /api/opportunities: Company-only; creates new posting linked to CompanyProfile.
   - GET /api/opportunities: Filterable by type, location, and regex text search.
   - GET /api/opportunities/:id: Detailed posting view with populated skills and company.
   - PUT /api/opportunities/:id: Company owner-only update.
   - DELETE /api/opportunities/:id: Company owner-only deletion.
   - POST /api/opportunities/:id/apply: Student-only; applies to posting with duplicate
     guard while isolating matchScore and matchReasoning for Dev 2's engine.
   - PATCH /api/opportunities/:id/applicants/:studentId: Company owner-only status update.

4. Skill Taxonomy Endpoints (/api/skills) -> skillRoutes.js & skillController.js:
   - GET /api/skills: List all taxonomy skills with category/search filters.
   - GET /api/skills/:id: Detailed skill data.
   - POST /api/skills, PUT /api/skills/:id, DELETE /api/skills/:id: Admin skill management.

2.5 INTELLIGENCE & DOMAIN ENGINES (server/src/utils & services)
--------------------------------------------------------------------------------
1. Match Engine (server/src/utils/matchEngine.js & matchingController.js):
   - Computes weighted, explainable match scores between student skill vectors and
     opportunity requirements.
   - Provides granular breakdown: matched skills, gap skills, and human-readable reasoning.
   - Endpoints mounted at /api/matching.

2. AI Roadmap Generator (server/src/controllers/roadmapController.js & geminiService.js):
   - Integrates Google Gemini AI to analyze candidate gaps against opportunity specs.
   - Automatically synthesizes step-by-step "How to become eligible" learning roadmaps.
   - Includes deterministic fallback generation if external AI API keys are unset.
   - Endpoints mounted at /api/roadmaps.

3. Live Project Pipeline (server/src/controllers/projectController.js & projectRoutes.js):
   - Facilitates industry problem statement publication, student bidding, and faculty mentorship.
   - Milestone completion tracking.
   - Automatic Skill Elevation: When a project is marked completed and signed off,
     the platform automatically upgrades the student's profile skills to 'project'
     verified evidence with elevated levels.
   - Endpoints mounted at /api/projects.
